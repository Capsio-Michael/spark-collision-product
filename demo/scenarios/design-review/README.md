# 设计评审合成用例

**仅供演示和交互设计。** 虚构企业“澄川智造”、人物、对话、项目和评审意见均为新写的合成材料；本目录没有客户报告、真实录音、实际转写或公开许可素材。不能由文字推断语气、情绪或人格，也不能把角色说出的事实当作已核实的外部事实。

| 文件 | 用法 | 规模 |
| --- | --- | --- |
| [`M1-品牌官网设计评审.md`](M1-品牌官网设计评审.md) | 第一场：一条主洞察在会议内经追问、反例、复述和条件认同形成；案例条件另成洞察 | 78 轮，约 4,000 汉字 |
| [`M2-展会专题回看.md`](M2-展会专题回看.md) | 后续场：增加“展会专题可以更鲜明”的场景条件；可信依据得到补证 | 28 轮，约 1,500 汉字 |
| [`insights-annotations.fixture.json`](insights-annotations.fixture.json) | 给前端复制的预置内容、洞察版本和 38 条原话/关系标注 | **内容 fixture，不是 v0.1 API 响应** |

两份 Markdown 可以直接作为 TXT/MD 输入材料。主流程建议先展示 M1 后的结果，再展示加入 M2 后的结果；如果浏览器仅载入预置标注，应明确标“合成预置结果”，不能模拟实时 AI 完成。现有本机报价 mock 引擎不会从本用例自动产出此 JSON。`meeting_id` 分别为 `M1`、`M2`，段落 `P001`–`P078`、`Q001`–`Q028` 是人工编写的稳定定位；它们不是会议时间戳。

JSON 中每条 `quote` 是对应段落的连续子串；`content_type` 与 `relation.type` 分开。`relation.target_claim_id` 总是指向本 fixture 的具体主张，跨 M1/M2 的连接保留原文。`明确认同` 只表示认可设计理解，绝不等于批准上线。M2 对“所有页面都要克制”的过度概括加以限定；M1 原始理解本身已明确限定为品牌官网首页，不制造假的历史错误。重要性仅解释来源和条件，不提供伪精确分数。`voice_delivery` 保持未知。

前端接入建议见 [Demo 指南](../../../docs/demo-guide.md)，口播与失败退路见 [Demo 脚本](../../../docs/demo-script.md)。后续若要改成正式服务响应，先与引擎方确认字段、引用完整性和版本语义；不要直接把 fixture 发给现有 v0.1 客户端冒充联调成功。
