## 用户引擎与服务侧依赖

既定分工是用户负责后端引擎与整个服务，一鸣负责交互与体验。因此以下事项需要用户启动并与一鸣共同冻结，不宜将其描述成一鸣已经完成：

1. 确认 v0.1 的最小真实联调面：`health`、项目、材料/原文、分析任务、总览、详情、版本、纠错与导出；明确 mock/live。
2. 增补 `meeting_id`、会议内标注、跨会议关联、按场去重计数、评分规则版本/分项、独立的趋同状态与评分快照。现有 `spark` 路径是认知变化来源，不能代替主题频次。
3. 以可定位原话为唯一证据基础，保留条件、分歧、历史和未批准状态；分析失败或没有新信息时如实返回，不自动执行外部任务。
4. 真正启动本地服务后，与一鸣共用一套合成数据做浏览器端到端验证，包括刷新、引文、版本与导出。前端的 91 项测试不能代替这一步。
