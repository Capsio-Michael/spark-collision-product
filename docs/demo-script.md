# 智慧火花碰撞｜三分钟 Demo 脚本

配套 [前端与用例指南](demo-guide.md) 和 [合成材料](../demo/scenarios/design-review/README.md)。**以下点击路线是待一鸣接入的演示目标，不是已经验收的当前页面。** 彩排前先核实每个点击点。使用本设计评审内容时，始终显示“合成文字／预置标注演示”；不要把它说成真实 AI 刚分析完成。没有音频，不讲语气或情绪；没有上线批准，也不讲任务执行。

## 三分钟逐步点击与口播

| 时间 | 页面动作 | 可直接说的口播 |
| --- | --- | --- |
| 0:00–0:25 | 停在唯一“上传资料”入口。选 `M1-品牌官网设计评审.md`，或在已标明“预置合成演示”的页面打开 M1 状态。不要演假等待。 | “企业里一次设计评审，往往不是一句需求。这里是一场**合成的完整多轮工作讨论**。入口只要上传资料；背后会管理来源、洞察和证据。今天这组设计评审洞察是预置标注示例，用来说明体验，不是实时 AI 结果。” |

| 0:48–1:38 | 展开 M1 的形成路径。依次点 P002、P004、P010、P028、P029、P063、P064；每次可见原话。 | “P002 只有‘大气’。P004 说明她反对促销海报，P010 给出反例：随便找的工厂照片也不可信。设计师在 P028 复述为‘信息克制、项目依据可核查’，客户在 P029 加了业务范围要看得懂这个条件，P064 才认可**当前设计理解**。认可理解，不是批准发布。” |

| 2:43–3:00 | 回 Dashboard，小青蛙收为小尺寸，不遮挡证据。 | “最终留下的是客户在**不同页面任务下**的评价标准，而不是替客户做决定。下一步如何使用洞察，交给用户。” |

若现场展示的是独立小青蛙预览，只能说“这是可接入的外观与状态动效样例”；不得把手动切换“思考/完成”说成系统真实处理进度。正式工作台接入前不要把预览混在主点击路线里。

## 90 秒压缩版

1. **0:00–0:18，唯一上传入口**：打开 M1 合成文字或已明确标注的预置结果。“一场会议里，需求不会只出现一句话；今天演示的是预置标注，不是实时分析。”
2. **0:18–0:52，Dashboard 到详情**：点主洞察，连续点 P002“大气”、P004“促销海报”、P010“素材图不可信”、P029“业务范围要看懂”、P064“认可当前理解”。“多轮追问把含混词变成有条件的专业感。”
3. **0:52–1:16，加入 M2 后的版本**：点内部标明的合成切换，或从同一上传入口加入 M2；看 Q003、Q023。“展会专题可以鲜明，可信依据仍要保留；旧版和原话都在。”
4. **1:16–1:30，原话与边界**：点一条引文回原文。“这是可追溯的客户理解，不是发布批准或效果保证。”

## 失败时的诚实退路

- **新用例尚未进入工作台**：停用“上传后自动出现本案例洞察”的说法，直接打开两份合成稿与 `insights-annotations.fixture.json`，按 P002→P004→P010→P029→P064→Q003→Q023 讲来源和修正；如有可用静态图，只称“内容原型”。
- **服务连接或分析失败**：保留原页面错误；不要切到预置页面假装任务刚成功。说“当前 API 的 mock 只覆盖另一套报价案例；这份设计评审还在做内容与接口联调”，再用稿件/fixture 讲清预期体验。
- **引文跳转失败**：不声称已可追溯；打开对应 Markdown，按段落号查找原句。引用定位没有通过时，在验收清单保留未完成。
- **状态动画失败**：直接隐藏小青蛙动效，保留上传、卡片和原文；不要用动画掩盖处理状态。
- **时间不足**：用 90 秒版，只展示一条主洞察、一处条件认同、一处跨会范围修正；不跳到旧报价官网或 PPT 冒充同一个产品流程。
