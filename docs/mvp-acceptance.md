# MVP 范围与验收（定义阶段）

以下均为待实现验收，不是已完成声明。今天用**一个项目**和 **3–5 场会议/访谈/聊天**验证；每场使用一份合成或明确获准的短文本、Markdown 或粘贴记录。案例必须显式标记“合成”或记录授权；不放客户私密数据。

## 范围内

- 导入、查看原始记录与定位片段；本地保存。
- 会议内标注：每场讨论中的智慧点、支持/质疑/补充/反例、适用条件及原话链接。
- 跨会议标注：相同智慧点的重复、补强、冲突和趋同；保留各场证据，不误并不同条件。
- 结果首页：关键关注点、按会议去重的出现频次、可解释的重要性分数、独立的趋同状态、智慧变化与证据缺口。
- 智慧点详情：跨会议时间线、各场标注、原话链接、分数构成与判断版本。
- 新增一场讨论，更新覆盖、评分和聚合认知，查看前后版本。
- 可读导出（建议 Markdown），包含日期、材料范围、结论类型、引文定位、判断历史与未解决问题。
- 用户可在结果处纠错；关键冲突请求确认。有限时间可先做最小纠错入口，但不能暗示已确认判断被自动改写。

## 验收用例

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 打开智慧点详情并点击引文 | 每个关键结论有真实引文，点击到对应记录的原文片段并能辨认位置；无来源则不展示为事实。 |
| A2 | 两段讨论条件不同（例如小团队/大团队） | 条件被显示并保留为两条或明确的条件分支，不误合并成无条件结论。 |
| A3 | 一人认同建议但未批准执行 | 页面只记观点认同/建议，不出现“已批准行动”，也不触发外部任务。 |
| A4 | 新会议只重复已知信息 | 允许显示“无新火花”，不生成虚构的认知突破；若确有独立证据，可更新覆盖计数。 |
| A5 | 新讨论反驳旧判断 | 看到修正依据与新旧版本；旧原文、原条件和先前确认状态不被抹去。关键冲突尚未确认时保持待确认。 |
| A6 | 导入后刷新/重开 | 项目、原文、标注和判断版本仍在，本地数据未丢。 |
| A7 | 导出项目结果 | 文件可由普通文本阅读器打开，含引文出处、判断版本和证据缺口；重新读入不要求。 |
| A8 | 关注点涉及不同提问方式 | 去重人数与讨论覆盖可查，主动提起和被问回应分开；未提及者不被计作不感兴趣。 |
| A9 | 材料不足以支持隐藏约束或动机 | 输出“待验证/证据不足”，不猜人格、隐秘动机或硬凑六类结果。 |
| A10 | 一场会议反复提及同一智慧点，或同一场有多份记录 | 会议内可有多条标注；跨会议频次只计该会议一次，原话都可回溯。 |
| A11 | 同一智慧点出现在多场会议 | 展示涉及会议数/总会议数、去重发言者、主动/被问；每条跨会议关联能点回对应会议内标注与原话。 |
| A12 | 高频议题同时存在明确反对或不同条件 | 重要性可以高，趋同仍显示“有分歧”；不同条件分支和少数反例不被多数票覆盖。 |
| A13 | 查看重要性分数 | 分数展示规则版本、会议覆盖、独立发言者和明确业务取舍的分项依据；没有依据不给对应分，未讨论不算反对。 |
| A14 | 新会议带来支持、质疑或关键的一次性约束 | 评分、趋同状态和判断版本可比较；低频但影响决策的约束可单列“需关注”，旧快照及原文仍在。 |

## 不做

音频转写、OCR、多人权限、企业系统集成、客户私密数据处理、外部任务自动执行、模型训练、大规模会议批量处理，以及“100 人”规模能力保证。首次演示仅证明样例闭环；评分权重、性能、泛化和生产安全性均待后续验证。

## 验收记录建议

每项记录：用例编号、会议与输入记录 ID、预期、实际、原话链接/截图、通过/未通过、问题负责人。展示前手工走通 A1–A7 与 A10–A13；A8–A9、A14 作为认知质量门槛。若时间不足，缩减页面装饰或案例数量，不硬编码虚假评分或把未实现项说成已通过。
