联调工作台选择“我的调研项目”，即可查看已通过接口导入、保存和分析的四份材料。顶部标记“模拟引擎结果”，与“报价授权边界调研 · 示例”的预设快照区分。

1. 点击“材料列表”，查看 M1～M4 四份已分析材料。
2. 点击“项目总览”，v3 显示“本次无新火花”；报价关注点为 4/4 场、5/5、有条件趋同。
3. 打开“报价的确认边界”，进入“原话证据”，选择 M1～M4 标注并定位原文。
4. 点击“认知历史”，v1 只有 M1＋M2，v2 加入 M3 补充条件，v3 加入 M4 增加印证。v2→v3 应显示“证据增强，判断未改写”。
5. 在所选历史版本中点击“导出结果”，确认版本与材料范围，再下载 Markdown。v1 不含 M3、M4。

单项目服务已保存这组演示记录，不要重复提交同场材料来重新演示。重演认知变化可查看三版历史；如需从空项目重走导入，应使用新的数据库和独立前端来源，不删除现有数据。

## 从空项目走通的顺序

使用 `examples/pricing-boundary/` 中的原文件。每份材料选择“合成案例”，日期未提供可以留空，参与者身份按原文填写。

| 批次 | 文件与会议标识 | 参与者 | 操作与预期 |
| --- | --- | --- | --- |
| 1 | M1.md→M1；M2.md→M2 | 客服负责人；销售负责人 | 提交后选择待分析材料，开始分析，生成 v1；2/2 场、4/5、条件待核实 |
| 2 | M3.md→M3 | 运营负责人 | 增量分析生成 v2；3/3 场、5/5、有条件趋同 |
| 3 | M4.md→M4 | 项目负责人 | 增量分析生成 v3；4/4 场、5/5、有条件趋同，本次无新火花 |

“所属会议标识”是可选字段，由人明确填写，保存、编辑暂存、刷新和提交均保留。不从文件名自动推断。该模拟服务每场只接收一份材料；同场多文件返回明确错误，草稿保留并解锁，便于修正。前端分组显示能力不表示服务已支持同场多文件导入。

## 启动或重启

在项目根目录的一个终端运行（需要可用的 Python）：

```powershell
python -X utf8 -m engine.server --port 8076 --db var/browser-integration.db
```

在另一个终端进入 frontend 并启动预览（需要 Node.js）：

```powershell
cd frontend
$env:PORT = '5201'
npm run dev
```

随后打开联调工作台，必要时点击“连接引擎”，填写上述服务地址。已有项目的浏览器记录应连接同一数据库；不要用新数据库冒充原项目继续提交。关闭并重新打开服务不会清空 SQLite。

## 自动复跑检查

在 frontend 目录执行：

```powershell
npm test
npm run test:integration
```

若 Python 不在 PATH，可先将环境变量 `SPARK_PYTHON` 设为本机 python.exe 的完整路径。集成脚本会使用独立随机端口、独立数据库及内存工作区，退出时关闭自己启动的服务，不操作已有演示项目。

脚本检查实际导入、分析、轮询、引用定位、旧版隔离、Markdown、幂等重试、CORS、同场拒绝后的草稿恢复、纠错 501 不写入，以及服务重启后的 SQLite 数据与前端缓存恢复。结果、报告和数据库位于 `frontend/.artifacts/mock-integration-*`，属于本地忽略文件，不进 Git。

## 已知边界

- 未接入真实模型，只识别冻结合成案例。不能承诺任意新会议自动产生可靠洞察。
- 纠错保存接口明确返回 501 `NOT_IMPLEMENTED`；界面保留原判断，不伪造成功，也不把明确拒绝当成待确认写入。
- 服务按任务接口返回并支持查询，但当前模拟分析在请求内完成，不能据此宣称真实后台任务调度或并发性能。
- 服务端详情尚未返回完整认知碰撞卡，部分六维内容仍为证据缺口。前端不以预设示例补全实际接口结果。
- 用户项目的报告直接来自服务端，完整程度由其实现决定；示例报告的完整卡片展示不等于服务端已实现全部内容。
