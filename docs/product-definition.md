# 产品定义（定义阶段）

## 目标与使用场景

用户希望跨多次对话回答：“和 100 个人交流后，他们真正表达了哪些关注点、为何如此、分歧在哪里、我们学到了什么？”今天只用 3–5 份短记录验证这一体验，不能把小样本说成 100 人的结论。面向持续项目记忆，不做一次性会议摘要，也不要求用户逐条审核 AI 标签。

## 核心对象

| 对象 | 最小字段与用途 |
| --- | --- |
| 项目 | 名称、创建时间、材料范围、当前认知版本。今天仅一个。 |
| 讨论记录 | 文本、来源类型、日期、参与者标识（可匿名）、授权/合成标记、版本。 |
| 原话片段 | 稳定片段 ID、记录 ID、字符区间或段落定位、原文。引文可点击并高亮定位；不可编造定位。 |
| 智慧点 | 稳定 ID、主题、适用条件、当前表述、置信/证据缺口。相近词不必是同一智慧点。 |
| 相互标注 | 片段对智慧点的支持、质疑、补充、反例或条件限定；标明是主动提起还是被问回应。认同仅是观点证据。 |
| 判断版本 | 旧表述、新表述、变更原因、依据片段、有效条件、时间。新发言不能自动覆盖已确认判断。 |
| 行动 | 仅经明确批准才记录为“已批准行动”；建议、赞同、待验证事项均不等于批准。产品不得自动执行外部任务。 |

## 首页与详情

首页先给可读的关键关注点、讨论覆盖和智慧变化，再显示分歧、证据缺口与“本次无新火花”。关注点不是词频榜：至少呈现去重发言人数、主动提起人数、被问回应人数、涉及记录数/总记录数，并保留“未讨论/材料未知”。不由未提及推断不感兴趣，也不猜人格或隐秘动机。若输入不足，显示“证据不足”，不要给伪精确排名。

智慧点详情按支持、质疑、补充、反例、条件限定组织片段，保留原话、来源与定位。不同适用条件的观点并列展示；只有语义与条件足够一致才合并。新增记录后展示哪些判断被增强、被修正或仍有争议，并能查看旧版本。

## 证据与推断边界

1. **事实**：材料可直接确认的事件或原话；他人自述仅证明其“这样说过”，不证明外部事实成立。
2. **他人观点**：明确归属的解释、偏好、判断或认同；不能升级为项目决定。
3. **AI 推断**：列依据、推理、适用条件、替代解释和待验证缺口；与原话视觉区分。
4. **已批准行动**：需要可追溯的明确批准证据和批准者。没有就保持“建议/待确认”。

分析方法参考现成“智慧火花碰撞” skill 的六个视角：关键事实、认知突破、隐藏约束、AI 运营含义、可复用机会、下一验证问题。六项是检查角度，允许某项为空并说明材料缺口；不为填满栏目制造结论。真正的认知突破需有旧认知、冲击证据、新框架、判断含义和验证动作；旧认知未记录时标注“分析前提，非原话”。隐藏约束与可复用机会也应标为有边界的假设，不能由单个案例宣称普遍成立。

## 更新机制（产品目标，尚未实现）

导入 → 保存原文和稳定定位 → 抽取有证据的主题与相互标注 → 按语义及条件聚合 → 比较既有判断 → 生成新版本或标注“无新信息” → 展示结果。若新证据与已确认判断发生关键冲突，向用户提出最小确认问题；常规纠错由用户在使用时发起，纠错也留下版本和理由。导入或更新失败时保留原有数据，避免静默覆盖。

## 成功信号

陌生观众能从首页读懂一个关注点和一次判断变化，点开原话核查依据，再导入新讨论看到变化及旧版本。若记录只重复已知信息，页面如实显示没有新火花。
