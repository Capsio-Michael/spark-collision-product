# 产品定义（定义阶段）

## 目标与使用场景

把同一项目的多次会议、访谈和聊天整理成持续演变的项目记忆。用户希望回答：“和 100 个人交流后，他们真正表达了哪些关注点、为何如此、分歧在哪里、我们学到了什么？”今天只用 3–5 场合成或明确获准的短讨论验证交互，不能把小样本说成 100 人的结论。AI 分析与聚合，用户直接看结果，在使用时纠错；仅关键冲突请求确认。

## 核心对象与两级标注

| 对象 | 最小字段与用途 |
| --- | --- |
| 项目 | 名称、材料范围、当前认知版本。今天仅一个。 |
| 会议 | 稳定 ID、日期、议题、参与者标识（可匿名）、来源与授权/合成标记。访谈和聊天也作为一次讨论场次处理；同一场会议的多份记录不重复计数。 |
| 讨论记录与原话片段 | 原文、版本、所属会议；片段有稳定 ID、字符区间或段落定位。引文可点击并高亮定位，不编造原话或定位。 |
| 智慧点 | 稳定 ID、主题、适用条件、当前表述、证据缺口。相近词或不同条件不自动合并。 |
| 会议内标注 | 某会议的原话片段对智慧点的支持、质疑、补充、反例、条件限定或认同；记录发言者、主动提起/被问回应、原话定位。认同仅是观点证据。 |
| 跨会议标注 | 将不同会议中的标注关联到同一智慧点或条件分支，说明重复、补强、修正、冲突或趋同；保留各会议原始标注和关联理由。 |
| 判断版本 | 旧表述、新表述、变更原因、依据片段、有效条件、时间与确认状态。新发言不自动覆盖已确认判断。 |
| 评分快照 | 算法版本、输入会议范围、分项分数、原始计数与生成时间；新讨论后可比较变化，不改写旧快照。 |
| 行动 | 只有明确批准才记为“已批准行动”；建议、认同、待验证事项均不等于批准。产品不得自动执行外部任务。 |

## 从出现频次到重要性

**跨会议重复出现是重要性信号，计量单位是具有实质证据的不同会议，而不是词或句子出现次数。** 同一会议中多次提及、同一人重复说法、复制的记录都不能把会议数抬高。每个智慧点显示“涉及会议数 / 已导入会议总数”，并能展开每场会议的原话。这个分母说明材料覆盖，不代表未提及者不感兴趣。对某议题未讨论的会议另记为“未知”，不要计作反对。

今天可用一条**演示评分规则，待真实数据校准**：重要性分数 0–5 = 不同会议中有实质证据的场次（最多 3 分）＋至少两位独立发言者各 1 条证据（1 分）＋有原话证明它影响明确的业务取舍或决策（1 分）。展示分项和原始计数，不把分数冒充统计概率。主动提起与被问回应单独显示；两者都可作为证据，但不能用被问次数制造“自发关注”。同一发言者跨会议可增加会议覆盖，不能增加独立人数。一场会议中出现的重大约束或风险即使分数低，也可单列“需关注”，并说明依据。

**重要性、趋同程度和证据把握分开展示。** 高频但反复被质疑的议题可能很重要，却没有趋同；趋同只在语义及适用条件一致、存在明确支持且主要异议被解释时标为“趋同中/已趋同”，否则标“仍有分歧/证据不足”。保留少数反例，不用多数票抹除。把握程度来自来源质量、覆盖与可核查性，不由重要性分数自动推导。

合成示例：M1 提出“跨区报价需要人工确认”，M2 在另一个团队再次提出，M3 说“标准目录价可直接发送，但定制报价仍需确认”。系统可显示“3/3 场涉及报价确认边界”及其评分依据；在条件分支厘清前，趋同状态仍为“有分歧”，不能写成“所有报价都须人工确认”。M1 若重复说三次，会议覆盖仍只计一场。

## 首页与详情

首页呈现关键关注点、按可解释分数排列的智慧点、讨论覆盖、趋同/分歧状态及智慧变化；证据不足时不给伪精确结论。每项可看不同会议如何标注同一智慧点。至少呈现去重发言人数、主动提起人数、被问回应人数、涉及会议数/总会议数；不猜人格或隐秘动机。

智慧点详情先给当前判断及适用条件，再按会议时间线显示支持、质疑、补充、反例与原话。跨会议关联要能返回每场会议内标注。不同条件并列为条件分支；新增讨论后显示分数、趋同状态与判断如何变化，并能查看旧版本。没有新依据时允许显示“无新火花”；重复证据可以增加覆盖，但不制造认知突破。

## 证据与推断边界

1. **事实**：材料可直接确认的事件或原话；他人自述只证明其“这样说过”。
2. **他人观点**：明确归属的解释、偏好、判断或认同；不能升级为项目决定。
3. **AI 推断**：列依据、推理、适用条件、替代解释和待验证缺口；与原话视觉区分。
4. **已批准行动**：需要可追溯的明确批准证据和批准者。没有就保持“建议/待确认”。

分析方法参考现成“智慧火花碰撞” skill 的六个视角：关键事实、认知突破、隐藏约束、AI 运营含义、可复用机会、下一验证问题。六项是检查角度，允许为空；不为填满栏目制造结论。真正的认知突破需有旧认知、冲击证据、新框架、判断含义和验证动作；旧认知未记录时标注“分析前提，非原话”。隐藏约束和可复用机会是有边界的假设，不由单例宣称普遍成立。

## 更新机制（产品目标，尚未实现）

导入并归属会议 → 保存原文和稳定定位 → 形成会议内标注 → 按语义与条件关联跨会议标注 → 计算可解释分数和趋同状态 → 比较既有判断 → 生成新版本或标注“无新信息” → 展示结果。关键冲突向用户提出最小确认问题；常规纠错由用户在使用时发起，纠错留版本和理由。导入或更新失败时保留原有数据。

## 成功信号

陌生观众能从首页找到一个跨会议重复出现的智慧点，区分它的高重要性与未趋同状态，点回不同会议的原话；再导入一场讨论看到计数、评分与判断的变化，旧版本仍可查看。
