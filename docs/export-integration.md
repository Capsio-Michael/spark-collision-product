# Markdown 导出：交互与引擎边界

## 当前交付

交互方已实现导出面板、版本选择、材料范围核对、Markdown 文件下载、失败重试，以及独立的合成报告。用户项目不使用合成内容补齐正文。真实引擎报告与端到端联调仍待伙伴服务验证。

入口位于项目页“导出结果”；窄屏也可操作。在认知历史页打开时，默认选择右侧正在查看的版本；其他页面使用已展示的分析版本。打开后即固定选择，不跟随后台最新版本变化。用户仍可主动选择另一历史版本。

## 读取流程与文件协议

1. 读取 `GET /projects/{id}/versions`，从已有的正整数版本中选择。
2. 按固定版本读取 overview，再读取该快照 source_record_ids 对应的 record 元数据；核对项目 ID、快照版本、材料范围与记录身份。面板只保留材料标题、来源、日期，不复制原文。
3. 用户点击下载时调用 `GET /projects/{id}/export?format=markdown&version=N`。正文由引擎生成，不由前端再次分析或拼接用户材料。
4. 先核对 HTTP 状态，再核对 `Content-Type: text/markdown` 与 UTF-8 编码；JSON 错误、HTML 页面、空文档或无效编码不会下载为报告。
5. 创建本地 Blob 下载文件。成功提示仅表示已交给浏览器下载，不宣称用户已保存到某个目录。关闭面板、切换版本或项目会忽略迟到结果，并中止正在下载的请求。

沿用接口契约 v0.1，不增加字段。`Content-Disposition` 的安全 `.md` 文件名可使用；CORS 未暴露该响应头时退回 `spark-collision-vN.md`，不阻止下载。伙伴可以通过 `Access-Control-Expose-Headers: Content-Disposition` 让前端读取自定义文件名。

面板核对版本与材料范围；纯文本文件没有结构化版本回执，真实报告的正文版本、引文、六维完整性和无未来信息仍需引擎联调与内容验收，不能仅凭 HTTP 200 判定完成。

## 文件与并行协作

- `frontend/src/export-view.js`、`export.css`：独立原生 dialog，样式使用 ex- 前缀。
- `frontend/src/export-model.js`：快照核对、版本切换、重试和关闭时的请求隔离。
- `frontend/src/api/export.js`：专门处理文件响应，复用 ApiError 类型，不改写现有 JSON 请求方法。
- `frontend/src/fixtures/export.js`：仅为合成案例生成可独立阅读的报告，复用已有按版本的数据源。每条引文须核对真实对应的合成段落，v1 不混入 v2 信息。
- `frontend/tests/export.test.mjs`：12 项检查。

app.js 只增加导出入口与协调；history-view.js 只增加所选版本的只读访问函数。详情和判断纠错模块由另一 agent 开发，本轮不改写其实现。导出不调用 analyses 或 corrections，不确认候选，也不批准行动。
